# FURPS+Требования (MVP подачи заявок на депозит)

FURPS+ — мнемоника для классификации требований к ПО:

- F — Functionality — функциональность
- U — Usability — удобство использования
- R — Reliability — надёжность
- P — Performance — производительность
- S — Supportability — поддерживаемость (включая сопровождение, масштабируемость, документирование)
- '+' — +Constraints — дополнительные ограничения (безопасность, совместимость, лицензирование, нормативные и т.п.)

| Код | Требования                                                                 | Комментарий |
|-----|----------------------------------------------------------------------------|-------------|
| F01   | Отображать список депозитов и ставок на сайте                             | Для новых клиентов; ставки должны быть актуальными. |
| F02   | Принимать заявки на депозит на сайте (ФИО + телефон)                      | Данные передаются в кол-центр. |
| F03   | Отображать персонализированные ставки и принимать заявки в интернет-банке | Только для авторизованных клиентов. |
| F04   | Подтверждать заявку в интернет-банке по СМС                                | Использовать существующий СМС-функционал АБС. |
| F05   | Хранить и согласовывать ставки в единой системе, а не в XLS-файлах         | Обеспечивает актуальность и аудит ставок для всех каналов. |
| F06   | Отправлять клиенту СМС при согласовании ставки и открытии депозита         | Не требует изменений в ядре АБС — интеграция через события. |
| F07   | Передавать заявки с сайта в систему кол-центра                            | Поддержка текущей микросервисной архитектуры кол-центра. |
| U01   | Соблюдать корпоративную дизайн-систему во всех интерфейсах                | Единый внешний вид: цвета, шрифты, компоненты. |
| U02   | Сократить подачу заявки до минимума действий                               | Не более 3 шагов в интернет-банке, 2 — на сайте. |
| U03   | Поддерживать мобильные устройства на сайте                                | Адаптивная вёрстка. |
| R01   | Обеспечить доступность 99,9% (включая резервный ЦОД)                      | Требует балансировки и переключения между ЦОД. |
| R02   | Защищать персональные данные при передаче (TLS 1.2+)                      | Обязательно для ФИО и телефона. |
| R03   | Не вызывать АБС напрямую из интернет-банка в режиме реального времени      | АБС не выдержит нагрузку; использовать асинхронную интеграцию. |
| R04   | Сохранять заявки при сбое АБС (очередь + повторная обработка)             | Гарантирует надёжность обработки. |
| P05   | Отвечать на действия клиента за ≤ 500 мс                                  | Особенно — загрузка ставок и отправка заявки. Возможно CDN |
| P06   | Масштабировать новые компоненты горизонтально                             | За исключением АБС (только вертикальное масштабирование). |
| P07   | Ограничивать частоту обращений к АБС (не более 10 запросов в секунду)     | Защита от перегрузки. |
| S01   | Использовать технологии, уже применяемые в банке                           | .NET, Java, MS SQL, Oracle, PostgreSQL. |
| S02   | Не модифицировать ядра АБС и интернет-банка                                | Избегать зависимостей от подрядчиков. |
| S03   | Вести полную техническую документацию                                     | Для поддержки и развития системы. |
| S04   | Обеспечить сквозное логирование и мониторинг                              | Включая трассировку по сервисам. |
| +R01  | Новые компоненты должны работать с текущими платформами (.NET 4.5, Java 8+) | Совместимость — обязательное условие. |
| +R02  | Kafka сейчас нельзя подключить напрямую к интернет-банку                   | Требуется промежуточный адаптер или отложить до миграции. |
| +R03  | Интеграция со СМС — только через асинхронные события                      | Чтобы не править PL/SQL-процедуры в АБС. |
| +R04  | Запрещено использовать XLS-файлы как источник ставок                      | Это создаёт риски ошибок и несогласованности. |
| +R05  | Обеспечить соблюдение ФЗ при работе с персональными данными               | Получениесогласий на обработку, периодический аудит, шифрование. |
| +R05  | Обеспечить соблюдение регуляторки и информирование о страховании вкладов  | Для многих клиентов важно чтобы вклады покрывались страховкой согласно ФЗ |
